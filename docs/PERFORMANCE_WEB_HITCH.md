# 웹 첫 등장 프레임 지연

2026-09-11, Godot 4.7.2 단일 스레드 Web export, WSL Firefox 155.0 WebGL2, 1600×900에서 측정했다. 고정 seed 73129의 자유 모드 전장에서 AI와 카메라 진행을 멈추고 실제 미사일 발사·월드 연기 생성·자폭·요격 실패 표시·레이저·플레어·채프를 실행했다. Master만 음소거하고 발사 오디오 생성 경로는 포함했다. 효과는 정상 프레임으로 감쇠한다. 이 수치는 지속 교전 FPS나 GPU timestamp가 아니라, 이벤트 이후 `process_frame`과 `frame_post_draw`를 기다린 프레임 간격이다. 브라우저 타이머 해상도는 1ms다.

기준 커밋 `992fb96`의 첫 발사 최대 프레임은 386ms와 369ms, 첫 연기는 84ms와 68ms였다. 발사 함수 CPU는 약 5ms여서 생성 함수의 실행 시간만으로 설명되지 않았다. 수정본 측정 후 원본을 다시 실행해도 재현됐다. WebGL 함수 추적은 진단에만 사용하고 성능 비교에서는 제거했다.

## 변경과 검증

실제 전장의 카메라·환경·그림자 맵에서 발사 섬광과 미사일·연기·레이저·요격 실패·플레어·채프를 준비한다. 효과 자체의 국소 광원까지 켜고 끈 상태를 렌더하며, 생성 순간 알파가 0인 궤적은 가시 상태로 진행한다. 생성 재질은 작전 동안 참조를 보존한다. 준비용 미사일은 전투 registry·표적·외부 게임 신호 연결 없이 실제 연기 분리·자폭 경로를 거치며, 광원 종료까지 렌더한 뒤 폭발 풀과 잔류 연기를 정리한다. 게임의 입자 수·수명·효과 표현·탄약·진행 시간은 유지한다.

아래는 이벤트별 최대 프레임 간격(ms)이다. '중간 수정본'은 미사일 첫 등장만 먼저 개선했거나 종료 경로 준비 전의 계측이다. 원본 전체와 같은 기준선으로 섞지 않는다. [원본 프레임 데이터](PERFORMANCE_WEB_HITCH.json)에 각 실행을 구분했다.

| 구간 | 원본 / 해당 경로 준비 전 | 최종 1차 | 최종 2차 |
| --- | ---: | ---: | ---: |
| 첫 미사일 발사 | 원본 386 / 369 | 27 | 27 |
| 첫 미사일 연기 | 원본 84 / 68 | 32 | 27 |
| 첫 폭발 감쇠 180프레임 | 중간 수정본 99 | 41 | 43 |
| 요격 실패 표시 | 중간 수정본 102 | 32 | 33 |
| 레이저 | 중간 수정본 60 | 29 | 27 |
| 채프 | 중간 수정본 129 | 30 | 28 |

최종 1차의 반복 폭발 감쇠는 최대 38/39ms, 2차는 44/40ms였다. 최초 준비 시간은 원본 17.25–17.66초, 최종 20.47/23.09초로 늘었다. 다운로드나 WASM 초기화 이전 대기는 포함하지 않고 앱 효과 예열부터 전장 준비 완료까지 잰 시간이다. 셰이더 컴파일을 앞당기는 대신 로딩 시간이 증가하는 변경이며 전체 브라우저와 장시간 교전의 모든 멈칫을 해결했다는 의미는 아니다.

월드·규칙 79개, 플레이 흐름 79개, 앱 흐름 7개, 낮밤·그림자 7개로 총 172개 테스트가 통과했다. 준비용 섬광과 실제 포대의 가시성·탄약 구분, 월드 궤적의 가시·그림자 데이터, 표본 제거 후 재질 보존을 회귀로 확인했다. 웹 진단은 준비 후 폭발 슬롯 32개가 모두 돌아왔는지도 검사한다. 일반 Web export의 실제 메뉴→새 게임 진입과 작전 시간 진행, 도시 100/100·위협 단계 1을 확인했고 웹 런타임 오류는 없었다.

## 재현

재현 도구는 `tools/missile_hitch_check.tscn`이다. 실제 창에서는 `godot --audio-driver Dummy --path . --scene res://tools/missile_hitch_check.tscn`으로 실행할 수 있다. 웹에서는 별도 검증용 checkout에서 임시로 이 scene을 main scene으로 설정하고 Web preset의 `tools/*` 제외를 해제해 export한다. 제품의 기본 main scene과 export 제외 규칙은 유지한다. 결과는 콘솔의 `HITCH_RESULTS`와 웹의 `window.airscainHitchResults`에 기록된다. 이벤트마다 기본 10프레임 안정화 후 12프레임을 기록하며, 폭발 소멸은 중간 공백 없이 추가 180프레임을 기록한다. 첫 발사/연기/폭발은 세 번, 나머지 효과는 두 번 반복한다.
