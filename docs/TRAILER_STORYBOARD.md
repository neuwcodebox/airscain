# Airscain 출시 트레일러 촬영 콘티

상태: 촬영 전 설계. 아래 시간·구도는 편집 목표이며 실제 게임 창에서 촬영 가능성과 가독성을 확인해 확정한다. 완성 영상이나 검증된 촬영 결과를 뜻하지 않는다.

## 1. 영상의 중심

**“당신이 설계한 방공망이 도시를 지킨다.”**

관객에게 보여줄 것은 한 전장의 방어 과정이다. 먼저 위협과 도시를 이해시키고, 플레이어의 배치가 연결된 방어를 만든다는 것을 보여준 뒤, 새로운 접근 방향에 대응한 결과로 절정을 만든다. 무기 소개 카드, 전장 선택 화면, 경제·보급 설명은 이번 본편에서 제외한다. 다양한 기능을 한 번씩 보여주는 것보다 하나의 플레이 경험을 기억하게 한다.

- 60초 / 1920×1080 / 60fps / 한국어·영어 각 1종. 초 단위 경계는 60fps 타임라인의 편집 기준이며 구간은 시작 포함·끝 제외다.
- 화면 진행 방향: 위협은 왼쪽 → 오른쪽, 요격은 중앙·오른쪽 → 왼쪽. 도시를 오른쪽 뒤에 유지한다. 근접 컷도 같은 방향을 유지한다.
- 전장 후보: `island_city`(평탄한 섬 도시). 기존 캡처 seed `73129`를 첫 후보로 확인하되 해당 레이아웃에서 해안·도시·배치 공간이 적합한지는 실촬영으로 결정한다. 임의의 고정 월드 좌표 대신 도시·해안·합법 배치점 기준으로 구도를 맞춘다.
- 고정 시간대: 밝은 늦은 오후. 한 분 안에 낮·밤을 섞지 않는다. 바다 위 궤적과 건물의 명암을 읽을 수 있는 광량을 우선한다.
- 기본 출연 자산: 기본 지휘통제소, 저·중고도 레이더(`search_radar`), 미사일 포대(`missile_battery`), 근접방어기관포(`close_in_gun`). 같은 전장에서 시작부터 끝까지 위치를 유지한다.
- 위협 후보: 첫 공습은 중저고도 공격 UAV, 후반은 다른 접근 방향의 소형 UAV를 중심으로 구성한다. 센서 감시 고도·포대 교전 조건에 맞는 조합으로 실제 테스트한다. 단순히 화면을 채우려고 탄도탄·레이저·HPM 등을 추가하지 않는다.

## 2. 구도와 편집의 공통 규칙

아래 위치는 영상 프레임 왼쪽 위를 (0%, 0%)로 하는 구성 목표다. 아직 측정하지 않은 카메라 월드 좌표나 UI 위치를 확정값처럼 쓰지 않는다. 실제 게임 UI는 원래 배치를 유지하고, 카메라를 움직여 중요한 전투가 UI 아래로 숨지 않게 한다.

| 구도 | 화면 구성 | 카메라 시작값 | 용도 |
|---|---|---|---|
| A: 전술 중경 | 바다·접근로 x=5–35%, 방어선 x=38–65%, 도시 x=67–88%. 주요 교전은 y=28–65%. | 수평에서 내려다보는 각도 약 35–42°, 고정 방위각. 줌은 이 세 영역을 한 화면에 담도록 결정. | S01–S05, S07–S08. 시선과 공간의 기준. |
| B: 발사 근경 | 포대가 x=58–74%, y=55–78%. 발사·비행 여백은 왼쪽 위 x=15–55%, y=18–50%. | 포대의 아군 측 후방 사선. 내려다보는 각도 약 15–25°, 기존 렌즈 우선. 지형·건물 관통 없음. | S06. 포대와 도시의 관계를 잃지 않는 가까운 시점. |
| C: 근거리 방어 | 기관포 x=62–76%, y=58–76%, 표적 x=25–45%, y=30–48%. 도시 건물은 오른쪽 배경. | 방어선 안쪽에서 바다 방향을 바라보는 낮은 사선. 표적과 포구를 함께 담는 거리. | S09–S10. 사격 방향·탄막·결과를 함께 읽기. |
| D: 최종 전술 전경 | A보다 조금 넓게. 도시 x=66–88%, 방공망 x=36–65%, 바다 x=5–32%. 왼쪽 아래 카피 공간 확보. | A와 같은 방위각, 완만한 후퇴. 기존 장비 배치가 식별되는 범위까지만 확장. | S11. 모든 계층이 한 공간에서 작동하는 증거. |
| E: 엔드카드 배경 | 도시를 오른쪽 1/3에 남기고 중앙은 복잡한 마커·연기 없이 확보. | D의 후퇴를 이어가되 마지막 6초는 거의 정지. | S12. 게임명과 행동 유도에 시선 집중. |

- 주인공은 한 컷에 하나다. 새 항적·배치·발사·격추를 동시에 강조하지 않는다.
- 게임 화면을 좌우 반전하지 않는다. UI 글자와 위협 방향이 바뀌므로 카메라 방위로 해결한다.
- 공간 연속성을 유지하는 하드 컷을 기본으로 한다. 글리치, 휩팬, 매 컷의 줌 효과, 합성 화면 흔들림은 쓰지 않는다.
- 사용자 조작 컷은 실제 커서·배치 프리뷰를 쓴다. 동작을 보여준 뒤 커서를 빈 영역으로 이동한다. 장식용 클릭 파문·가짜 HUD는 만들지 않는다.
- 청색 C2 관계선은 선택 자산에 접한 실제 관계만 표시된다. 한 번에 전체 연결망이 나타나거나 데이터가 선을 따라 이동하는 것처럼 합성하지 않는다.
- 촬영에는 사건 앞뒤 최소 2초의 여유를 둔다. 실제 배치와 탐지 지연이 콘티보다 길면 대기 시간을 컷으로 생략한다. 결과를 앞당기는 게임 규칙 변경은 하지 않는다. 이후 컷은 이미 경과한 게임 시간을 이어받는다.
- 음향 지시는 믹싱 의도이며 청취 완료를 뜻하지 않는다. 피크가 발생하는 모든 컷에 효과음을 추가하지 않고 실제 중요한 사건을 선별한다.

## 3. 12개 컷 상세

### S01 · 00:00–00:04 · 도시 앞에서 시작되는 요격

- **첫 프레임:** A 구도. 도시가 오른쪽에 이미 보이고, 왼쪽 바다 위에 탐지된 UAV 2–3개가 들어온다. 포대는 중앙 아래. 이미 작동 중인 기존 방어선으로 시작한다.
- **동작:** 0.5–1.5초 사이에 포대가 발사하고, 요격탄이 왼쪽 위로 뻗는다. 3초 부근에 화면 중앙 왼쪽에서 첫 요격 결과가 보이는 테이크를 선정한다.
- **카메라:** 정지. 첫 4초 안에 카메라까지 움직여 표적을 놓치게 하지 않는다.
- **UI/문구:** 정상 게임 HUD, 항적·자산 마커 유지. 카탈로그와 상세 선택창은 닫힘. 카피·로고 없음. 무한 예산 등 자유 모드 표시는 사용하지 않는다.
- **소리/연결:** 실제 발사음 한 번과 요격음에 무게. 요격의 짧은 잔향을 S02로 이어 공간을 연결한다.
- **채택 기준:** 설명 없이 도시·위협·방어 세 요소가 보이고, 작은 재생 크기에서도 요격 위치를 찾을 수 있어야 한다. 읽히지 않으면 적 수를 늘리지 말고 촬영 구도를 좁힌다.

### S02 · 00:04–00:08 · 플레이어의 선택

- **첫 프레임:** A 구도를 유지한다. 초기 공습이 정리된 뒤, 기존 포대와 도시가 그대로 남아 있다. 다음 공격에 대비하는 국면이다.
- **동작:** 4.0초에 실제 방공 자산 메뉴를 열고, 5.0–5.8초에 저·중고도 레이더를 선택한다. 6초부터 해안 안쪽의 합법 배치점으로 커서를 이동한다. 메뉴 스크롤 탐색은 생략하고 목표 항목이 보이는 상태를 준비한다.
- **카메라:** 정지. 카탈로그가 가리는 쪽을 피하도록 전장 초점을 촬영 전에 조정한다.
- **UI/문구:** 원래 구매 메뉴·가격·프리뷰를 유지. 5.2초부터 “방공망을 설계하라.”를 전장 하단의 빈 영역에 표시하고 S03까지 유지한다. 메뉴·프리뷰 힌트를 가리면 카피를 S03으로 늦춘다.
- **소리/연결:** 선택음만 짧게. 위기 효과음을 과장하지 않는다. S03은 같은 프리뷰 위치로 연결한다.
- **채택 기준:** 첫 8초 안에 플레이어가 설치할 장비를 고른다는 행동이 보인다.

### S03 · 00:08–00:12 · 빈 공간이 방공망이 된다

- **구도:** 레이더 후보를 (43%, 56%), 기존 C2 방향을 (69%, 42%) 부근에 둔다. 도시는 계속 오른쪽 뒤. 배치 반경 원 전체를 억지로 담기보다 프리뷰와 연결 상대를 읽게 한다.
- **동작:** 8–9.5초는 프리뷰와 실제 청색 연결선을 보여준다. 9.5초에 합법 배치 확정. 프리뷰가 실제 레이더로 바뀌고, 클릭·예산 감소 등 기존 피드백이 정상 발생한다. 10–12초는 관객이 새 장비 위치를 기억할 시간을 준다.
- **카메라:** A에서 필요한 만큼만 가까워진 구도를 컷 시작에 사용한다. 클릭 중에는 이동하지 않는다.
- **UI/문구:** 배치 프리뷰·상태 힌트는 실제 표시 그대로. 카피는 11.5초까지 사라진다.
- **소리/연결:** 확정음 1회. 다음 컷에서 같은 장비를 중심으로 연결 관계를 읽는다.
- **채택 기준:** 갑자기 나타난 장비로 보이지 않고, 선택과 배치 확정의 결과임이 분명하다.

### S04 · 00:12–00:16 · 연결의 의미

- **구도:** 같은 전장. 지휘통제소를 선택해 새 레이더와 기존 포대를 잇는 실제 C2 관계선을 한 화면에 담는다. 선택창이 여는 실제 화면 영역 밖에 주요 노드를 둔다.
- **동작:** 12–13초에 실제 선택, 13–15.5초에는 선택 상태를 유지한다. 선 위로 가짜 광점이나 “탐지 성공” 같은 새 UI를 추가하지 않는다.
- **카메라:** 정지. 레이더 → C2 → 포대의 세 지점이 읽히는 거리로 조정한다.
- **UI/문구:** 선택 패널·실제 연결선 유지. 별도 카피 없음. 작은 능력 수치를 읽어야만 이해되는 구도는 피한다.
- **소리/연결:** 음악은 낮은 추진력을 유지. 15.5초에 선택을 해제하고 다음 컷의 항적에 시선을 넘긴다.
- **채택 기준:** 연결이 실제 네트워크 상태와 일치한다. 공간상 한 화면에 담기지 않으면 짧은 레이더 선택 컷과 C2 선택 컷으로 나누되 시간을 추가하지 않는다.

### S05 · 00:16–00:21 · 탐지가 교전으로 이어진다

- **구도:** A. 새로 설치한 레이더가 왼쪽 아래, 첫 공격 편대는 왼쪽 위에서 오른쪽으로 접근. 기존 포대는 중앙 아래에 유지한다.
- **동작:** 16–18초 사이에 실제 센서 관측으로 항적이 나타나는 구간을 채택한다. 18–20초에는 표적을 향해 포대가 조준하고, 20–21초에는 발사 직전 동작을 보여준다. 탐지되지 않은 표적에 합성 마커를 넣지 않는다.
- **카메라:** 고정. 한 번에 읽히는 항적은 우선 2–3개를 목표로 촬영한다.
- **UI/문구:** HUD·실제 항적 유지, 카피 없음. 첫 항적에 불필요한 툴팁을 띄우지 않는다.
- **소리/연결:** 탐지 알림은 핵심 1회가 들리게 믹싱. 다음 컷의 실제 발사를 이어 붙인다.
- **채택 기준:** 새 레이더가 해당 항적을 실제 제공하고 연결된 포대가 그 지식으로 교전하는지 로그·상태로 확인한다. 단순히 동시에 일어난 다른 교전을 인과처럼 편집하지 않는다.

### S06 · 00:21–00:25 · 설계의 결과, 미사일 발사

- **구도:** B. 발사대는 오른쪽 아래, 미사일이 뻗는 왼쪽 위에 충분한 여백. 도시 실루엣 일부를 오른쪽 배경에 남긴다.
- **동작:** 조준 종료 → 발사 → 연기 궤적이 이어지는 4초. 포대 모델만 도는 장면이 되지 않게 발사 순간을 중심에 둔다.
- **카메라:** 고정에 가까운 짧은 이동. 기체 추적용 급회전 없음. HUD를 숨긴 연출 컷.
- **UI/문구:** HUD·선택 반경·커서 숨김, 카피 없음.
- **소리/연결:** 발사음을 전면에 두고 음악을 잠시 낮춘다. S05의 사건을 반복 재생하지 않도록 같은 진행 시간에서 다른 카메라로 촬영한 구간을 맞춘다. 충분히 재현되지 않으면 과장 없이 별도 연속 발사 사건으로 연결한다.
- **채택 기준:** 발사대·미사일·연기 진행 방향이 읽힌다. 피사체가 프레임 밖으로 잘리는 테이크는 재촬영한다.

### S07 · 00:25–00:30 · 다른 접근로

- **구도:** A와 같은 방위각으로 전장 초점을 조금 아래로 옮긴다. 새 소형 UAV는 왼쪽 아래 (20%, 62%)에서 도시 외곽 (73%, 54%)으로 접근한다. 앞서 싸우던 방향의 연기 일부가 왼쪽 위에 남아 공간을 연결한다.
- **동작:** 새로운 접근 방향을 2초 정도 보여준 뒤 근거리 방어를 준비한다. 표적을 일부러 무적화하거나 포대 명중률을 낮추어 위기를 조작하지 않는다. 실제 사거리·교전 조건이 다른 경로를 고른다.
- **카메라:** 컷 후 정지. 방향 전환을 강조하려고 화면을 180도 돌리지 않는다.
- **UI/문구:** 정상 HUD·탐지된 표적 마커. 27초부터 “빈틈을 메워라.”를 하단 여백에 표시한다.
- **소리/연결:** 음악의 음색·리듬으로 긴장 상승. 반복 경고음으로 피로를 만들지 않는다.

## 5. 촬영 인과관계와 검수

- S01은 기존 방어선, S02–S04는 추가 레이더, S05–S06은 그 레이더가 제공한 항적으로 교전, S07–S10은 새 접근로와 추가 기관포의 대응, S11은 확장된 전체 방공망이다. 시작부터 무방비였던 도시에서 갑자기 포대가 쏘는 모순을 만들지 않는다.
- 기존 방어선의 센서가 새 레이더의 교전을 대신 설명하는 문제가 없도록 감시 범위·항적 제공자를 검증한다. 촬영 가능한 실제 시나리오가 안 나오면 콘티의 인과 설명을 수정한다.
- 전장·방위각·자산 위치·시간대·실제 게임 시간·표적 ID·항적 제공자·격추 주체를 샷 기록에 남긴다. 카메라만 바꾸어 같은 사건을 재촬영할 때 사건 시점이 일치하는지 확인한다. seed만으로 완전 결정성을 보장한다고 가정하지 않는다.
- 촬영은 실제 경제·배치·교전 동작을 유지한다. 공개 화면에 샌드박스 전용 버튼, 무한 예산, 임의 조작된 HUD 수치를 노출하지 않는다. 설정·저장 파일은 사용자 플레이와 격리한다.
- 콘티와 대조하여 실제 창에서 구도 검수 → 움직이는 원본 검수 → 전체 편집본 검수 → 작은 화면·무음 검수 → 최종 믹스 청취 순으로 확인한다. 대표 프레임 몇 장만으로 동영상 전체를 합격 처리하지 않는다.
- 이 문서는 제작 지시서다. 미촬영 컷과 미청취 믹스는 검증 완료나 납품 완료로 표시하지 않는다.
