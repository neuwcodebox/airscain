# PLAN.md

## 1. 문서 목적

이 문서는 현재의 플레이 가능한 첫 버전에서 `SPEC.md`의 최종 제품 목표까지 확장하기 위한 고수준 작업 순서를 정의한다.

세부 구현과 작업 분해는 각 단계에서 현재 코드를 확인한 뒤 결정한다. 각 단계는 실행 가능하고 플레이 가능한 세로 단면으로 끝내며, 미래 기능의 빈 골격을 미리 만들지 않는다.

---

## 2. 진행 원칙

- 현재 단계에 필요한 범위만 설계하고 구현한다.
- 두 번째 실제 사용 사례가 생긴 뒤 공통점을 추출한다.
- 기능과 함께 필요한 UI, 시각화와 테스트도 완성한다.
- 저장 기반 도입 후 추가되는 상태는 저장·복원까지 함께 확장한다.
- 새 콘텐츠는 기존 콘텐츠와 다른 전략적 역할이 있을 때만 추가한다.
- 단계 완료 후에도 기존 플레이 흐름과 성능을 유지한다.

### 진행 이력

- 2026-09-01: 형식 ID와 명시적 버전, 필수 상태 섹션을 검증하는 JSON 기반 plain-data 저장 문서를 도입했다. 알 수 없는 버전·누락 섹션·손상 JSON을 상태 변경 전에 거절하고 월드 좌표를 JSON-safe 배열로 변환하는 계약을 GUT 테스트로 검증했다.
- 2026-09-01: 세션 단계·시간·경제·통계, 도시 기능, Raid Director와 RNG, 배치 자산의 C2/doctrine 런타임 상태, 공격 UAV 임무 및 중립 조류 순찰 상태를 스냅샷에 포함했다. 로드 시 기존 scene 객체를 폐기하고 콘텐츠 ID와 runtime ID로 새 scene을 생성해 상태를 주입하며, 알 수 없는 콘텐츠는 현재 세션을 변경하기 전에 거절하도록 통합 테스트로 검증했다.
- 2026-09-01: 항적 생명주기·추정·분류·센서 기여 상태와 비행 중 요격체의 포대·표적 참조 및 비행 상태를 저장했다. 로드 시 센서/C2 graph와 참조를 runtime ID로 다시 연결하며, 손상 참조의 원자적 거절과 복원된 요격체가 기존 교전을 이어 격추하는 흐름을 GUT 전체 테스트로 검증했다.
- 2026-09-01: HUD에 저장·불러오기를 연결하고 `user://`의 기존 저장을 백업한 뒤 교체하는 파일 저장소를 추가했다. 저장된 seed로 지형·도시를 다시 생성하면서 runtime 상태를 복원하며, 실제 파일 왕복, 중단된 교체의 백업 복구, 중복 월드 노드 방지, 전체 44개 GUT 테스트와 1280×720 실제 게임 창을 검증해 4단계를 완료했다.
